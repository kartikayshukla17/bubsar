## Global Constraints (bind every task)

### Hard rules (from the spec's Definition of Done)
1. No LLM/model SDK anywhere in `src/`. `npm run lint` runs `scripts/guard.mjs`, which fails
   on model SDK imports and on any mention of browser credential stores (`Cookies`,
   `Login Data`, `cookies.sqlite`, `logins.json`, `key4.db`, `Safe Storage`) in `src/`.
   Code that must name such a thing for a test lives under `test/`, never `src/`.
2. busbar never reads browser credential stores, never types a password, never handles a
   cookie. Sessions stay inside the browser profile.
3. No secret value in run state, events, CLI output or UI. The Google client secret is never
   read, never navigated to, never shown.
4. Green means checked: `verified` only from a recorded check result (BB-05).
5. Plan before touch: no provider write without a plan the user saw and confirmed.
6. Local only: no network except the provider being wired and its verify endpoint.
7. `npm run typecheck`, `npm run lint`, `npx vitest run` all pass before every commit.

### Process rules
- **TDD, red before green, one test at a time.** Test only at these four agreed seams:
  1. **Core rules (pure):** diff/ownership, verify classifier, exit-code mapping,
     handoff/resume orchestration with the fake recipe, reducer.
  2. **Recipe vs fixture page:** the Google recipe driving real headless Chromium (installed
     Brave or Dia; Firefox in BB-08) through `BrowserDriver` against the local stand-in page.
     `it.skipIf(!browserAvailable)`.
  3. **CLI end to end (fake world):** spawn the built `dist/bb.js` with `BB_FAKE` pointing at
     a fake-world JSON file. Assert stdout/stderr/exit code/run state/fake-world state.
  4. **Verify HTTP + launch args:** verify request against a local stub server; pure
     launch-argument builders.
  No other test seams (no testing private helpers, no mocking internals).
- **No real Google, ever, in tests or while building.** No request to any `*.google.com`
  host. No headed browser windows on the user's screen. Tests that launch Chromium use a
  temp `--user-data-dir`, headless, and `keychain: "mock"` (see below) so macOS never shows
  a Keychain prompt.
- Never touch the user's real browser profiles or the real `~/Library/Application
  Support/busbar`. Every test sets `BB_HOME` to a temp dir.
- Node: run `eval "$(fnm env)" && fnm use` before node/npm commands (shell default is 22.17;
  the project pins 22.23.4).
- Commit at the end of the task on branch `mvp-browser-slices` with message
  `BB-0N: <summary>` and the trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
  Never push.
- At the end of each task, tick the ticket's acceptance boxes that tests or local runs
  proved, and add a `## Done (2026-11-22)` section to the ticket listing: tests added,
  decisions made, and a **`### Real-world checks pending`** list naming every acceptance item
  that needs Kartikay, his Google account, the sandbox OAuth client or a human at a browser
  (with the exact steps to run it).
- Product voice in CLI and UI copy: plain, honest, infra-literate; say what was checked and
  what wasn't. Never claim more than was proven.

### Shared architecture (every task builds within this; extend, don't fork)

Existing (BB-01): `src/core/board.ts` (Step with `from: string|null`, `to`; reducer; Action
union = event protocol), `src/core/config.ts`, `src/core/plan.ts` (`plan`, `resolveValues`,
`FLAGS`), `src/core/run.ts` (`Run`, `RunEvent`, `startRun`, `describe`, `RUN_DIR`),
`src/core/secret.ts`, `src/cli/bb.ts`, `src/cli/daemon.ts`, `src/cli/print.ts`,
`app/` (live board at `/`, demo at `?demo`/`?at=`), tests under `src/**/*.test.ts` and
`test/`. `test/helpers/project.ts` spawns the built CLI (`vitest` globalSetup builds it).

**Environment overrides** (all optional; production never sets them):
- `BB_HOME` — busbar's home (default `~/Library/Application Support/busbar`). Profiles live at
  `$BB_HOME/profiles/<project>/<browser>/`, created mode `0700`.
- `BB_FAKE` — path to a fake-world JSON file. When set, the CLI uses the fake browser driver
  and the fake Google console instead of real browsers. The fake world is the single source
  of truth for: installed browsers, Google session state, the OAuth client's lists, and
  scripted failures. The fake **writes its state back** to the same file so tests can assert
  on it (e.g. how many saves happened).
- `BB_GOOGLE_CONSOLE_ORIGIN` — replaces `https://console.cloud.google.com` (recipe tests
  point it at a local server).
- `BB_GOOGLE_AUTH_URL` — replaces `https://accounts.google.com/o/oauth2/v2/auth` (verify
  tests point it at a local stub).
- `BB_APPLICATIONS` — colon-separated app roots for browser detection (default
  `/Applications:~/Applications`).

**`src/core/browser/`** (BB-02 creates it):
- `browsers.ts`: `BrowserId = "brave" | "dia" | "chrome" | "edge" | "firefox"`;
  `InstalledBrowser = { id; name; executable; engine: "chromium" | "firefox" }`;
  `detectBrowsers(roots: string[]): InstalledBrowser[]` by bundle path
  (`Brave Browser.app/Contents/MacOS/Brave Browser`, `Dia.app/Contents/MacOS/Dia`,
  `Google Chrome.app/Contents/MacOS/Google Chrome`, `Microsoft Edge.app/Contents/MacOS/Microsoft Edge`,
  `Firefox.app/Contents/MacOS/firefox`).
- `args.ts` (pure, seam 4): `plainLaunchArgs(browser, profileDir, url)` — the un-automated
  window: no `--remote-debugging-*`, no `--use-mock-keychain`, no `--password-store=basic`,
  no `--enable-automation`. `automationLaunchOptions(browser, profileDir, { headless, keychain })`
  — puppeteer-core options: `pipe: true` (Chromium; never a port), `userDataDir`,
  `executablePath`, and `ignoreDefaultArgs` dropping `--use-mock-keychain` and
  `--password-store=basic` when `keychain: "real"` (production default). `keychain: "mock"`
  exists only so tests never trigger a Keychain prompt.
- `driver.ts`: the `BrowserDriver` interface. Minimum shape:
  ```ts
  interface BrowserDriver {
    detect(): InstalledBrowser[];
    /** Un-automated window on the profile. Resolves when the user presses Enter in the
     *  terminal or the browser process exits; then makes sure the process is gone so the
     *  profile is unlocked. */
    openPlain(browser: InstalledBrowser, profileDir: string, url: string): Promise<void>;
    attach(browser: InstalledBrowser, profileDir: string, o: { headless: boolean }): Promise<Page>;
  }
  interface Page {
    goto(url: string): Promise<void>;
    url(): Promise<string>;
    exists(css: string, timeoutMs: number): Promise<boolean>;
    values(css: string): Promise<string[]>;   // input values (or text) of every match, in order
    click(css: string, nth?: number): Promise<void>;
    fill(css: string, nth: number, value: string): Promise<void>;
    text(css: string): Promise<string | null>;
    close(): Promise<void>;                     // closes the whole automated browser
  }
  ```
  `puppeteer.ts` implements it with `puppeteer-core` (Chromium over `--remote-debugging-pipe`;
  Firefox over WebDriver BiDi in BB-08). `fake.ts` implements detect/openPlain/session check
  from the fake world.
- macOS: closing the last window doesn't quit the app. `openPlain` tells the user to sign in,
  then press Enter (or quit that window with Cmd-Q); after Enter, busbar terminates the
  plain process gracefully before any automated attach (profile lock).

**`src/core/recipes/google/`** (BB-03 creates it):
- `selectors.ts`: every recorded selector, named, with a one-line comment on why it was
  chosen, and a header saying **PROVISIONAL: recorded against the local stand-in, not the
  live console. Re-record against the real client page (see BB-03 Real-world checks).**
  Prefer `aria-label`/`name`/role attributes over classes.
- `console.ts`: the recipe's interface, which everything above it uses:
  ```ts
  type Lists = { redirectUris: string[]; jsOrigins: string[] };
  interface GoogleConsole {
    read(): Promise<Lists>;
    write(next: Lists): Promise<{ saved: Lists }>;   // edit, Save, wait for confirmation, read back
    close(): Promise<void>;
  }
  ```
  Implementations: `PageGoogleConsole` (drives a `Page` with `selectors.ts`) and
  `FakeGoogleConsole` (fake world). Typed failures, shared by both:
  `SelectorMissing(name)` → "Google console layout changed: `<name>` not found. Nothing was
  changed."; `ReauthRequired(url)` (any navigation to `accounts.google.com`, detected by host
  and path, never page text); `SaveRejected(googleText)`.
- Console URL: `${origin}/auth/clients/<client_id>?project=<project_id>`.
- Never press Save on a page whose lists weren't read in this same page load.
- Stand-in page: `test/fixtures/google-console/client.html` + a tiny local server helper in
  `test/helpers/` that serves it with mutable lists, an "Add URI" flow, per-entry delete,
  Save with a saved toast, and switches to simulate a save error or a redirect to
  `/signin` on an `accounts` host. Scrubbed: fake client ID, **no secret anywhere**.

**State files** in the project's `.busbar/` (all public, no secrets):
- `local.json`: `{ "google": { "browser": "brave", "session": "signed-in" | "signed-out", "checkedAt": "<iso>" } }`
  (written by login/status/logout; the daemon serves it at `GET /api/session` for the board's
  session chip).
- `state.json`: `{ "google": { "owned": { "redirectUris": [], "jsOrigins": [] },
  "planned": { "read": Lists, "next": Lists } | null, "checks": [ { "at", "uri",
  "result": "accepted" | "rejected" | "unknown", "status": number | null } ] } }`.
- `run.json` + `events.jsonl` as in BB-01. Add `appendEvent(projectDir, action)` in
  `src/core/run.ts` (reads the snapshot, reduces, writes snapshot, then appends
  `{ run, seq: seq+1, action }`). `plan`/`rewire` start a run; `apply`/`verify` append to the
  current run (start one if none).

**Steps after BB-03** (one strip per change, ids stay `google-redirect-N` / `google-origin-N`
in desired-list order, removals get `google-redirect-remove-N` etc.):
- replace: `from` = removed entry, `to` = added entry (pair removals with adds in list order)
- add: `from` = `""`, `to` = new entry → strip shows "New entry"
- remove: `from` = old entry, `to` = `""` → strip shows "Remove"
- `from === null` still means "not read" (BB-01 path, only when reading is impossible).
- An entry already present needs no step. Likely-stale entries go in the step's `note`
  (add optional `note?: string` to `Step`).

**Event protocol additions** (adding is fine, renaming forks demo replays):
- `{ type: "handoff"; id; note? }` → bay `turn`, mark `handoff`, phase `handoff` (BB-06).
- `{ type: "fail"; id; note }` → mark `failed` (BB-04).
- `checked` gains optional `mark` and `note`; the reducer prefers them over the step's
  declared `verify` (BB-05). Live runs always send them.
- New `Mark`s: `failed` (BB-04, label "Failed"), `rejected` (BB-05, label "Not accepted").
  Each gets a glyph in `app/components/mark.tsx` in the Flight Strip style and a place on
  `/kit`.

**Exit codes** (BB-07 formalises; earlier tasks use them already): `0` ok/verified, `1`
failed or refused, `2` stopped at a handoff, `3` finished but a required check is unknown or
not accepted yet.

### Task 5: BB-05 `bb verify` proves Google accepts the redirect URI

Requirements: `docs/superpowers/tickets/BB-05-verify-google.md`.

- Verify = plain `fetch` GET to `${BB_GOOGLE_AUTH_URL}` with `client_id`, `redirect_uri`,
  `response_type=code`, `scope=openid`, `redirect: "manual"`, no cookies, no browser.
- Classifier (pure): 3xx to an `accounts.google.com` sign-in/consent path → `accepted`;
  body/location containing `redirect_uri_mismatch` → `rejected`; anything else, including
  network errors, 429, captcha → `unknown`.
- Fixtures under `test/fixtures/google-auth/`: **provisional, hand-written** from Google's
  documented behaviour (no real requests); header comment says so; real recording is a
  pending check.
- Polling with backoff (5s doubling, cap 60s) up to `--wait <seconds>` (default 600); while
  waiting the strip stays `checking` with "waiting for Google to pick up the change"; on
  timeout mark `rejected` with "Not accepted yet. Re-run `bb verify` later." and exit 3.
  JS origins → `unexercised` with an honest note. Every result recorded in
  `state.json.google.checks`; `checked` events carry `mark` + `note`.
- Add the `rejected` mark (+ `/kit`).
- Seam tests: classifier on fixtures (seam 1); request shape against a local stub: no
  `Cookie` header, no redirect followed, offline → `unknown` (seam 4); CLI verify with the
  fake world + stub: verified path, mismatch path, timeout path with `--wait 0` (seam 3).

### Task 6: BB-06 re-auth mid-run becomes a "your turn" handoff

- UI: live handoff card, read-only: instruction, browser, "Press Enter in your terminal when
